## 1. Demo 的定义

**一句话**：打工人想提前下班，要躲开"找你对需求的人"的视线，从工位一路摸到电梯。路上要穿过健身房，那里的器械是掩护，也是和别人抢的资源。

**核心规则（已确认）**

1. **目标**：不被发现，慢慢走到电梯并按下，提前下班。
2. **视野**：每个巡逻 NPC 有一个类似手电筒的锥形视野，会转向、会扫视。玩家进入锥形范围，**警戒条**开始上涨，离开范围慢慢回落，满了就算被发现。
3. **移动速度**：慢走更安静（不容易触发警戒），快走和跑步警戒涨得更快，鼓励"慢慢走向电梯"。
4. **被发现**：被需求人拉回工位，扣时间，返回起点或上一个安全点，难度逐步升级（视野变大、巡逻变密）。
5. **障碍与掩护**：办公桌、隔断、盆栽、门、健身器械可遮挡视线；躲进遮挡后面警戒回落更快。
6. **健身房（默认设计，可调整）**：穿过它是必经路线。器械占住通道，需要等人用完或把人挤开；成功抢到并用完一组，可以获得一次性增益（比如短时间降低被发现速度），形成"抢器械换掩护"的玩法。
7. **结算**：用时、被发现次数、是否全程未被发现，给出评级。

一局目标 3 到 5 分钟，可以重开。想改任何一条先告诉我，再让 Opus 动手，不要边做边改。

## 2. 给 Opus 的硬性规范

- 项目根目录是 `D:\game championship`，Godot 4.7，GDScript，静态类型。
- 目录：`scenes/`、`scripts/`、`data/`（Resource 配置）、`assets/`（已整理好，遵守 `assets/README.md` 的命名规则）。
- **器械数据驱动**：每种器械一份 `StationData` 资源（名称、时长、收益、可用人数、动画名、站位点）。新增器械只加数据和美术，不改代码。
- **角色用状态机**：`Idle / Walk / Use / Queue / Pushed / Caught / Typing`，状态切换只走一个入口，退出时必须释放占用。
- **先占位后美术**：每个里程碑用色块先跑通，再换图。任何时刻游戏都必须能运行。
- 动画帧、碰撞、层级排序（Y-sort 加前后景层）按 `PLAN` 的美术规格走，48×48 格。
- 每个里程碑结束：提交一次 git，提交信息写清楚做了什么，不要攒大提交。
- 不得提交受授权限制的素材（见 `.gitignore`）。

## 4. 我的审查方式

每个里程碑提交后，我会做这几件事：

1. **静态检查**：读代码，查状态机漏转移、占用释放漏洞、信号泄漏、硬编码、类型缺失。
2. **自动检查**：用 Godot 无头模式加载项目、跑场景，捕获解析错误和运行时报错。
3. **行为测试**：用 Godot MCP 操作编辑器，运行游戏、截图、读调试输出，按验收标准逐项过。
4. **出报告**：问题按严重程度排序，写清楚复现步骤，反馈给 Opus 修，修完我复查。

## 6. 主要风险

| 风险 | 应对 |
|---|---|
| 抢器械的 NPC 容易死锁或抖动 | M1 先把占用、预约、超时规则定死；M3 加每个 NPC 的耐心值和强制换目标 |
| AI 出图风格不统一、帧不对齐 | 固定参考图和提示词模板；每张图过"缩放加对齐"检查；必要时手修 |
| 工期不够 | 器械种类和 NPC 数量是可裁剪项；核心体验（抢器械加躲需求人）优先 |
| 受授权素材被公开 | `.gitignore` 已排除；公开仓库前再确认授权 |
