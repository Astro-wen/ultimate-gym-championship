# AI 生成的玩家器械姿势（char_worker_*）

玩家角色（白衬衫挽袖、黑西裤、黑皮鞋、棕色短乱发，Q 版）使用 4 种器械的姿势帧。
全部为横向条带：每帧一格、格子等宽、从左到右为第 0..N-1 帧；透明背景，alpha 只有 0/255，无抗锯齿。
颜色量化到 `tools/art/palette.json` 的子集（`build_gym_poses.py` 里的 `WORKER_SUBPALETTE`，约 10 色），1px 深色描边 `#3a3a50`。

由 `tools/art/build_gym_poses.py` 从 `assets/generated/_raw/` 的 AI 原图生成（原图不进仓库），提示词见 `assets/generated/_prompts/`。

## 锚点约定

锚点 `(x, y)` 是格内像素坐标（原点为格左上角）：

- 站姿 / 侧面：`y` 是**地面线**，角色最低的不透明像素（鞋底）在第 `y-1` 行；`x` 是参考点所在列。
  在 Godot 里用 `Sprite2D`，设 `centered = false`、`offset = -anchor`，节点位置即脚底点。
- 卧推（俯视躺姿）：同样以脚底中心对齐（双腿左右对称，脚中心即身体中轴），另给出身体中心供摆到凳子上时参考。

## 已知不足

- 卧推的"举高"在俯视下只能靠杠铃位置区分（杠在脸前 vs 杠在胸腹），手臂伸直不明显；推举动画建议再用 Tween 让两帧之间平滑移动。
- 各帧由 AI 分别生成，发型细节、衬衫褶皱逐帧略有差异；已按头宽 / 身高归一化并对齐锚点，播放时不抖，但细看会有细节跳变。
- 跑步 4 帧中 1、3 两帧（腾空交叉）比较相似。

# v2：与 LimeZu 行走图同一个人、同一画风（`v2/`）

v1 是 1px 细节的动漫比例，和游戏里的 LimeZu 角色画风不统一，而且玩家上器械会"换一个人"。
v2 让 4 个角色（玩家 + 3 个常客）使用器械时**就是**他们各自 LimeZu 行走图里的那个人：

- 像素颗粒：LimeZu 角色是 16×~22 的逻辑像素画放大 3 倍；v2 同样在**逻辑分辨率**上作画，再最近邻 ×3，
  每个 3×3 块对齐格子的 3px 网格（逻辑网格从格子 (0,0) 开始）。
- 比例：逻辑高度 = 该角色行走图对应方向站立帧的高度（÷3 后，玩家/红/绿 22，蓝 25 含头顶两撮；卧推躺姿 23，
  蓝 24 以塞进 24 行的格子）。大头、短手短脚由参考图约束。
- 颜色：只用该角色行走图 12 帧里出现的颜色（11–20 色），加 LimeZu 健身器械图集里的 6 个灰（杠铃、哑铃）。
  alpha 只有 0/255。轮廓 1 逻辑像素，颜色 `#3a3a50`（行走图描边色；已是 `#46465e` 的边缘像素保持不变）。

## 生成流程

1. 参考图：把该角色 12 帧从行走图裁出，最近邻放大，作为 `codex exec -i` 的第一张参考图
   （**只存在本地临时目录，不进仓库**；只发送 LimeZu 角色帧，不发送其它素材）。
2. 每帧单独出图，提示词见 `assets/generated/_prompts/char_<char_id>_<action>_<frame>_v2.md`
   （由 `tools/art/gym_poses_v2_config.py` 生成）。第 1 帧之后把已选定的第 0 帧原图作为第二张参考图；
   卧推第 0 帧最后是以选定的第 1 帧作参考重画的（原先第 0 帧脸被杠铃挡住 / 杠铃片太大）。
3. 原图存 `assets/generated/_raw/v2/<char_id>_<action>_<frame>.png`（gitignored），然后：

```
python tools/art/build_gym_poses_v2.py [--only player:bench_press ...] [--preview <仓库外目录>]
```

`build_gym_poses_v2.py`：去品红背景 → 裁包围盒 → 量化到角色色板 → 由同色像素游程长度估计 AI 图自己的
像素块尺寸并逐块取色 → 行数与目标差 ≤ 6 时删除/复制最冗余的整行（不会删掉眼睛、描边），否则直接按目标高度重采样
→ 卧推杠铃过宽时从左右外侧 1/3 删冗余列 → 去孤立像素、补描边 → 按锚点放进格子 → ×3。
行走图从本 checkout 的 `assets/sheets/` 读；在 git worktree 里自动去主 checkout 找，也可 `--sheets` 指定。

## 已知不足（v2）

- 卧推俯视下第 0/1 帧主要靠杠铃上下位置和手肘是否外展区分；两帧由 AI 分别生成，头发/脸的细节略有差异，
  杠铃两端经删列压缩，`goer_red` / `goer_green` 的杠铃几乎占满 96px 宽。
- `goer_red` 的卧推第 1 帧、跑步 4 帧、出拳 2 帧，`goer_blue` 的卧推第 1 帧，AI 原图像素块偏细（29–40 行），
  是按目标高度重采样得到的，比其它帧略"糊"（但仍是 3×3 块、同色板）。
- 跑步机 4 帧没有做上下起伏（脚都贴底行），需要的话在代码里对 1、3 帧上移 3px。
- 背面跑步时手臂只露出一点手，摆臂幅度小。
